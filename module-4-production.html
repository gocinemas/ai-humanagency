Module 4: Production vs Testing

Why your demo works perfectly. Why production fails. What testing misses. How to bridge the gap.

The Gap

You test your AI system with 100 clean examples. Success rate: 98%. You deploy to production with 1M real-world examples. Actual success rate: 75%.

What happened?

Testing vs. Production: The Gaps

Testing:
  • 100 hand-picked examples
  • Clean, formatted data
  • Typical edge cases only
  • No concurrency
  • Network: localhost
  • Volume: 1 req/sec
Production:
  • 1M user examples
  • Messy, malformed data
  • Weird edge cases (spellings, symbols, etc.)
  • 100s of concurrent requests
  • Network: intermittent latency
  • Volume: spikes to 100 req/sec

Real Production Failures

Issue 1: Encoding Problems

Your test data: "Café, London"

Production data: "Café, London" (different unicode encoding)

Result: Categorization fails silently. Model can't parse the input.

Issue 2: Timeout Under Load

Test: 1 request at a time → response in 2 seconds

Production: 100 concurrent requests → system overload → timeouts → cascade failures

Your monitoring didn't test concurrency.

Issue 3: Hallucinations on Real Data

Test: "Categorize this receipt from Tesco"

Production: "Categorize this receipt from [random store name user typed wrong]"

Model hallucinates store type. Categorization fails.

Why 90% of Production Bugs Are Integration Bugs

Testing focuses on: "Does the model work?" Production reveals: "Does the entire system work?"

  • Database connection timeouts
  • API rate limiting (you hit it faster than expected)
  • Data format mismatches (field name typos, encoding issues)
  • Redis cache misses leading to recomputation
  • Model inference queue filling up
Critical Insight: 71% of AI implementation time goes to integration, not model selection. Testing the model is 10% of the work. Testing the whole system is 90%.

How to Test Like Production

1. Staging Environment

Must have: A production-like environment where you can test before deploying.

  • Same infrastructure (databases, caches, load balancers)
  • Same data volume (or scaled version: 10% of production)
  • Same network conditions (latency, packet loss simulation)

2. Load Testing

Before production, simulate peak load:

  • Send 1000 concurrent requests
  • Ramp up gradually (test if autoscaling works)
  • Test failure modes (what happens if AI API times out?)

3. Data Validation

Before feeding data to the model, validate it:

  • Check encoding (UTF-8, not random unicode)
  • Check format (required fields present)
  • Check for suspicious patterns (injection attempts, junk data)
  • Reject invalid data with clear errors

4. Canary Deployments

Don't deploy to all users at once:

  • Deploy to 1% of users first
  • Monitor for errors (not test coverage — actual production errors)
  • Gradually ramp up to 100%

5. Production Monitoring

You must log and monitor:

  • Hallucination rate (% of outputs that are wrong)
  • Latency distribution (p50, p99)
  • Error rates (failed requests)
  • Model output variance (is output quality degrading over time?)
✓ Best Practice: Deploy observability infrastructure BEFORE deploying the model. If you don't measure it in production, you won't catch problems until users complain.

Your Production Readiness Checklist

  • Test with real data (not clean examples)
  • Test under load (100+ concurrent requests)
  • Test failure modes (API timeout, database error, etc.)
  • Test data encoding and format validation
  • Set up staging environment (mirror of production)
  • Implement canary deployments (1% first)
  • Deploy monitoring before going live
  • Plan rollback procedure
  • Have incident response playbook
  • Run post-mortem after any production issue
